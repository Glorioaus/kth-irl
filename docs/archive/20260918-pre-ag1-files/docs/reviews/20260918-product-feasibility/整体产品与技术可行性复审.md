# 整体产品与技术可行性复审

## 结论先行

**建议：调整路线，暂不按现行 N1 的 P1–P3 顺序开工；保留当前仓库和已验证工程底座，先做“人工基准先行的一单元业务效用验证”，再决定自动化接线投入。**

当前最需要证明的不是还能否接通两个准则，而是：系统能否在真实、多来源、存在冲突的材料中，选对评估单元，既不夸大也不漏掉有效信息，形成比分析员直接阅读更省力、更可靠的下一步尽调建议。现有证据不足以支持“已经具备专业自动评估效果”，也不足以断言“技术上做不出来”。

明确处置：

1. **不重新从零重写。** 原件、来源、Journal、恢复、受控队列、规则版本和 trace 继续保留；未受影响的历史工程验收不重做。
2. **不把旧 wheel 当专业正确性的真值。** 保留它作为历史行为比较基准；对证据用途、单元边界、适用性和行动政策，新增具名的方法审议建议，不在本轮修改。
3. **把人工参考和正负双向判别提前到新增实现之前。** N1 的用途分层、失败分流、可读输出和统一派发边界有价值，但应成为业务验证所需的工程子项，而非下一阶段本身的成功依据。
4. **近期按“人工负责专业结论、模型提供有源候选和反方”的责任边界试验。** 这不是已经决定永久放弃自动化；只有在有界验证失败或没有专业负责人时，才正式收缩为人工主审产品。
5. **一个窗口后作明确决策。** 业务判别与效用通过，才接入同一产品路径并逐步扩展；专业错误持续、全拒答或没有净收益，则停止扩六维/自动 D1，转人工主审或停止产品化投入。

依据最强的三点：KTH 原指南明确“成熟度不衡量创意质量或潜力”；旧实际主链仍让模型裁定准则和关键政策谓词；当前真实试点只有三条候选，专业请求、返回和该 job 的维度输出均为零。[S01][C02][C04][S08]

## 2. 真正的产品是什么

### 2.1 合理的核心需求

产品应交付的是**可追溯、可质疑、能支持有限行动的专业判断工作台**，而不是一个“六维分数生成器”：

1. 用户提交现有材料并确认问题，系统说明实际读到什么、遗漏什么。
2. 明确产品/市场/系统责任单元，避免拿同公司另一条路线的成绩证明本单元。
3. 将材料陈述、已核实事实、解释、假设、反证、缺口分开。
4. 对可公开核实的问题主动研究；只向项目方索取私有残余事实。
5. 用六维描述当前状态，用组织政策与专业推理讨论下一行动；不将等级直接变成投资结论。
6. 给出决定性支持与反对、下一项最有价值的验证、触发停止的事实，以及同源的简短与详细视图。

这些目标在早期 PRD 已经成立，不是本轮另造需求。路线图也明确：模块、schema、receipt 和单维纵切只能是内部使能，用户里程碑必须回答用户能完成什么判断。[S02][S03]

### 2.2 宣传、需求与可证明能力的差距

| 容易形成的宣传理解 | 原始需求与本轮判断 |
|---|---|
| “投资决策工具做完了” | 聊天同时说接口未写；不能解释为接收方 Windows 全链或专业质量已经通过。[S04] |
| “把材料交给工具就能得到专业结论” | 不应要求复杂 prompt，但必须确认主体、单元、行动、时点、外发和专业责任；关键人工工作不能藏在开发者后台。[S02][S04] |
| “六维等级准确，所以投资建议专业” | KTH 衡量发展进展，不衡量质量/潜力；高等级未必值得投入，低等级也未必不值得验证。[S01] |
| “正反模型辩论可消除偏差” | 上下文隔离能减少直接串线，不能保证模型知识独立、证据充分、最强反方被发现或专家判断正确。必须与更简单的单分析员方案对照。[C01] |
| “新版稳定了，所以结果可靠” | 封存重放稳定、文字改写不改事实、新证据重评的区分合理；反复复现同一个错误仍然是错误。[S05] |
| “同事长报告就是预期效果” | 可借鉴结构，但报告存在输入集、单元和权限差异，且无完整可核专业签审，不能作黄金答案。[S06][S07] |

### 2.3 设计理念的三个方向性风险

**第一，成熟度、投资价值、行动权限是三个不同问题。** 原始 PRD 已尝试分开，但历史报告仍出现“尽调/验证”“投资立项”“不建议外部投资”的语言混合。完整产品不能只保证 JSON 中不出现总分，还应证明政策判断确实回应资源上限、机会成本、可逆性和验证价值。[S02:第1、9节][S07][C04]

**第二，不能把一般性的专业目标伪装为可完全机械验证的合同。** “覆盖所有重大争点”“最强反方”“第一性原理”“一级市场 sense”都需要专业判断。引用完整、字段完整、论点 ID 连续是必要条件，不是充分条件。若认定这些语义问题都可由另一个模型自证，会形成没有外部专业锚点的验证循环。

**第三，完整性和成本之间需要产品取舍。** PRD 要求不以固定查询数/字数替代充分性，同时要求有界执行。两者不是必然矛盾：预算可限制动作，预算耗尽后保留未完成研究即可。但不能既许诺“所有争点充分覆盖”，又在预算用完时自动签发完整结论。冻结后任何实质补充都重走整链，也会增加真实使用成本；未来应审议依赖范围内的增量重评，不原样恢复旧复杂控制体系。

## 4. 旧实现到底做到了什么

### 4.1 值得承认和保留的能力

- **不是“只有 prompt”。** 批准源码存在真实的分层合同、单元处置、证据路由、专业 callback、研究门、累计评级、D1、D2、报告与恢复代码。
- **不只是模型直接吐一个等级。** TRL vertical 对准则覆盖、允许证据类、引用、最强反方来源和累计等级有确定性约束；这些约束具有明确工程价值。[C02]
- **确有历史完成产物证据。** 成功包保留两个多单元 macOS 影子运行的终态与阶段结构，不能因为缺少新仓兼容性就抹去；但其精确源码 revision、完整输入/提示/搜索/专业签审不足，不能升级成接收方同版本成功。[S11]
- **失败经验有明确价值。** 行动入口、Windows 路径、错误丢失、研究分母、许可投影和外部结果未知，是可复用的设计反例；不需要再运行失败包证明一遍。

### 4.2 专业判断并未被确定性代码替代

批准源码中至少有两种不能混为一谈的路径：

1. `compile_existing_dimension_professional_runtime` 依次调用研究、正反、settlement、KTH mapping；mapping callback 返回 `criterion_dispositions`，vertical 再校验与计算等级。[C01]
2. `local_whole_chain` 的实际 provider-backed 路径按批次调用模型填写准则处置，接着应用语义检查和累计求值；它不是“所有 met 都由独立事实逻辑自动推导”。[C02]

所以，“最终等级由代码生成”只说明**等级聚合在代码里**；如果准则真假、证据类别或关键谓词由模型判断，专业不确定性仍在上游。结构更严格可以减少伪造和漏项，不能证明模型对技术环境、商业关系、法律权属的解释正确。

还应保留一个具体风险：旧 local `_compile_fail_closed_criterion_dispositions` 会把带理由但无引用的 `met/partial` 转为 `insufficient`。这避免无源升权，却可能把模型合同缺陷显示成业务不足；本轮只确认该静态行为，不声称已复现某份报告因此误判。[C02]

### 4.3 D1 的“确定性”没有解决商业判断

local D1 的两个谓词是 `action_authority_is_valid` 和 `material_risk_has_bounded_validation`。后者由模型 `policy_choice_adjudicator` 输出布尔值和允许前提引用；程序检查引用集合后按“全部匹配才 YES”合成结果。Chair 被禁止改值，主要整理理由。[C04]

这比让写作模型随意改决定好，但**决定性的专业裁量只是被移到一个布尔字段，并未消失**。同一 local 路径中 YES/NO Advocates 的输出进入 Chair，但 PolicyChoice 的上下文不直接消费两方已封存论证；不能仅凭生成过正反文本就声称正反对抗已经决定最终政策值。

另一个 `decision_authority.py` API 有更强的外部政策选择和盲化合同，不能把它的存在自动嫁接到 local 主链或历史报告。正式接续时必须指定使用哪条实际路径，不能从同包挑选最强模块说明来证明整包效果。

### 4.4 D2 是信息投影，不是第二轮投资决策

独立 `d2_projections.py` 从同一源对象编译 Executive/Analyst/Audit 并可逐文件重建。local 主链却另外构造 `local-d2-projection.v1`，再把 D1、D2、维度交给报告模型；其 `_validate_report_output` 检查覆盖单元、禁止未执行评级、最低长度和部分 TMRL 文案，并非逐句业务含义等价验证。[C07]

因此，旧报告可能拥有正确同源字段，又在自由文字中扩大判断。这是静态可见的保障边界，不是声称所有旧报告都发生了此错误。8 月 28 日新增报告事实闭包和改写隔离设计值得借鉴，但其新内核/新路径未经本轮运行或专业验收，不能自动升级基线。[S05]

### 4.5 人工参与：需要、接口存在、实际发生要分开

| 人工职责 | 已知事实 | 本轮不能证明 |
|---|---|---|
| 确认单元与问题 | 聊天明确要求 HITL；旧控制包和新输入均有边界数据 | 历史成功样本中的人究竟确认了什么、花了多久 |
| 专业判断 | 文档允许专家提供带依据意见；程序可消费受控人工返回 | 同事本人或独立行业专家逐条核验过完整报告 |
| 组织行动政策 | 设计要求有权限人选择政策与资源边界 | 某份报告的政策已代表本组织实际决策制度 |
| 运行排障 | 原日志及复盘显示开发者/IT 参与入口和恢复 | 普通用户能独立复现同样效果 |
| 报告审阅 | 有写作、检查和投影流程 | 实际人审质量和净节省工时 |

若关键专业内容其实由少数熟悉项目的人在过程中选择材料、解释单元、纠错和反复调度完成，那么这仍可能是有价值的分析服务，但不是已经验证的自动产品。应计量这部分贡献，不贬低也不隐藏。

## 5. 输入输出告诉了什么

### 5.1 微玖不是“只有 BP”

已知原始输入是 BP 加四份访谈。四访谈同时包含客户样品观察、采购条件、量产限制、内部计划和不完全一致的技术/商业陈述。它们足以构造**比 BP 页17更有区分力的专业验证题**，但尚不足以直接宣称 TRL5/6 met。[S06][S13]

以影目访谈 Q6 为例：有“已上机验证、基本符合准入标准”的受访者陈述，也有“后续小批量试制”的限制。至少应能同时保留：

- 这是被记录的客户侧积极反馈，不能把它丢成“无任何信息”；
- 不等于已经获得完整配置、测试方法、阈值、样本量和长期供货证明；
- 不能将单绿的观察外推给单片全彩、车载或光互连。

这里没有替企业定级，也没有核实访谈真实性。原文、访谈者身份、时间、纪要来源及是否存在原测试记录，仍须按用途分别核查。

### 5.2 当前真实候选暴露了语义跳跃，不证明复核有效

真实候选将 BP 页17的路径/规划解释为相关环境集成测试，将“送样验证”解释为接近运行规格。引文 hash 正确，并不能支撑这两步推论。它们应作为开发用负例保留。[S08]

该历史 job 的专业请求、专业返回、维度输出均为零。资格阻断避免了错误进入后续链，但**不能据此声称专业复核发现并纠正了错误**。这也不是企业技术“不达标”的正式结果。

### 5.3 旧报告既有过度肯定风险，也有过度否定风险

- 平台 v0.1.4 微玖稿把公司多产品汇成一个六维表，叙述混合单绿、红光与全彩；同事当晚明确指出分数和产品/市场拆分异常。它是负例，不是成功样本。[S06]
- 同事完整稿/Word 的结构更细，但一些单元将用途受限或缺少指定工件解释成“未形成等级”，还出现对第三方实验室、自有系统能力等较强要求。是否必要，应回到产品责任、准则原文与专家解释，不应因为分数低就默认专业。[S07]
- 官方指南允许项目特定解释；TMRL 能力可来自顾问和伙伴，BRL 商业模式可用多种格式表达。这不自动否定旧报告，但足以否定“必须自己拥有全部终端能力”“没有指定文档就必然没有相应能力”等无条件推断。[S01]
- 同事 MD 的开头只列三个 Owner Evidence 项，而原始材料池不止三个文件。证据块数不等于输入文件数，不能仅据此认定漏读；也不能认定全部原始材料均已被等量专业消费。缺少该报告精确运行 manifest 与原文覆盖对应，保留未知。[S07]

### 5.4 Monako能做什么对照

同事12页稿、用户5页稿的分数和数字不同，不能因此归因为“模型差”。BP 在 ZIP 内外是重复字节；重写的技术计划不是同一输入；公开研究时点、模型、政策和具体单元未完全对齐。[S06]

可复用的是“可退预约不等于全价购买”“远程接管不等于本体工作站”“签融资文件不等于到账”等判别问题。不可复用的是同事的 YES/NO 或具体等级作为标准答案。

**后续对照必须同时记录输入集合、重复关系、时点、单元、方法、模型/角色、研究快照、组织政策和实际人工干预。任一不一致先解释差异来源，不作严格 A/B。**

## 6. 当前新实现应保留和替换什么

### 6.1 保留

保留现仓、内容寻址原件、来源实例、不可变投影与输入身份、Journal、封存响应、读时复核、精确 job/response 引用、受控队列、六维不聚合、显式方法版本、失败/未知结果留痕及本地隔离工作方式。

保留已通过的工程能力。9月15日独立裁决明确通过的是本地机械入口、受控人工/合成六维、trace 和恢复，不是实际专业分析；自包含收口进一步解除正常运行的旧 wheel 路径依赖。这两项都是真实进展，无须重新否定或全面复验。[S09][S12]

六维 kernels 暂保留为**可测试的历史规则实现**，不是无需质疑的专业真值。未来确需改变的准则语义要单独裁定、版本化，再测试受影响路径。

### 6.2 按业务验证需要替换或补齐

1. **资格总开关改为用途级判断。** 当前同 hash 多来源使独立性 UNKNOWN，继而总状态 needs_review；Proposal 和 runner 又要求 qualified。这会阻断本可作为受限自述读取的内容。[C09] N1 的拆分方向合理，但只有证明是重复实例时才可处理，不能全放 UNKNOWN。
2. **专业响应不能只剩 supports / does_not_support。** 当前提示、返回校验、内核语义串联会把缺支持映射成 not_met；必需字段只是 hints，且缺少准则特定布尔要求的完整合同。[C10][C12] 应分开支持、明确反证、材料不足与执行失败。
3. **让专业输入的发现成为受测能力。** 当前 job 的 quote、locator、单元由调用者准备，模型在给定片段内映射；它尚不是“全材料找关键证据”的产品。[C08] 不能只修复片段下游，而继续隐藏上游人工劳动。
4. **建立可读的人审与行动输出。** 当前 export 不是正式评估报告；真实人需要看到原文、解释、反证、缺项和下一验证，不应填内部 JSON。[C13]
5. **最后验证宿主全链。** 同一 Windows 入口从附件到审阅记录、停止与恢复，必须由目标使用者实际完成；不能由同机包隔离测试代替。

### 6.3 当前最明显的方向性偏差

当前重建较好地解决了“不要冒充、不要篡改、不要盲重发”，但对“能否发现重要信息、作出适度而准确的专业判断、减少人力”尚未取得对应证据。若继续先做大量资格/预算/兼容接线，再接受全部 insufficient 为主要阶段出口，可能得到可靠的记录系统，却没有验证评估产品。

这不是建议降低证据要求。**错误升权和无理由压低都需要被验证；把一个不充分的试验做得更可追溯，不能补足它缺失的判别力。**

## 7. N1 是否值得原样继续

**不建议原样继续；建议保留合同保护目标，改变试验输入、验收目标和执行顺序。**

| 现行 N1 内容 | 能检验什么 | 对本轮核心疑问的不足 |
|---|---|---|
| BP页17、TRL5-C1/6-C2 | 已知过度解释是否被复核拒绝；用途和精确引用能否接通 | 几乎预先知道不够证明高等级，不能充分检验真实正向支持和跨材料发现 |
| 一个人工冻结单元 | 防止本次运行串单元 | 未检验系统发现/区分单元，也未计量人工贡献 |
| 合成四类正反例 | 合同执行与失败分流 | 手填正确字段不能证明模型从真实材料得出它们 |
| P1–P3 后落实人工参考 | 允许连续推进工程 | 如果没有专家或方法分歧未解，会先把未经验证的边界固化为代码 |
| 专业复核完成但全 insufficient 可 complete_limited | 受限的诚信分析能力；计划已诚实保留 positive_quality=unverified | 这个终态不足以支持继续投入整体专业产品 |
| 同 CLI、恢复、预算、G1/G2/G3 | 必要的运行与治理能力 | 不直接测研究价值、专业增益、人工成本、用户能否采取合理下一行动 |

不能把 N1 描述为虚假验收：它已经明确不等于完整产品，也明确未验证正向质量。问题在于**当前 Owner 要决策的是产品方向，这个试验的成功条件不足以改变该决策**。[S14]

建议将 N1 降为后续有界验证的工程候选清单；BP页17保留为公开开发负例，不作新的盲测题，更不作为专业产品放行的主分母。

## 8. 决定可行性的五个假设

下列为建议采用的最小验证，不是已获授权的执行任务。阈值是产品验收提案，不是 KTH 方法规则。

| 假设 | 最小验证办法 | 完成标准与失败含义 |
|---|---|---|
| H1：真实材料能形成有信息量、边界正确的专业基础 | 用微玖 BP+四访谈；先让分析员与技术审阅者独立定位单元和关键主张，再处理分歧；模型在完整获准材料池中自主定位，不提供人工挑好的答案片段 | 找到至少一个可用受限正向事实、一个明确反对某被测主张的材料陈述、一个真实缺口；所有人工预先认定的决定性来源均须发现或明确报告读取阻断，不能强求 TRL5/6 met。若没有可判定参考，停止自动化接线，不以虚构材料凑平衡 |
| H2：模型能双向正确判断，旧用途/规则没有系统性误伤 | 冻结12个左右原子判断，覆盖单元/时态/客户反馈/技术证据/资金权限；将关键事实支持与“足以满足准则”分别标注 | 所有决定性项正确；非决定性项至少90%与审定参考相容，并列实际分子/分母；无关键无源支持、跨单元继承、执行失败转业务不足；真实正向与明确反证均须正确，不能全拒答通过 |
| H3：对抗复核比简单方案有净价值 | 固定材料与同一参考，比较“单分析员模型”和“独立正反＋有限交叉复核”，各做两次盲运行；不向模型提供旧报告/人工答案；比较总费用、延迟及人工时间 | 逐项报告纠正和新增错误；对抗方案须在准确性、重要遗漏或人工检查时间中至少改善一项，其他质量项不退化，并满足预先冻结的增量成本/延迟上限。只有提升无法在简单方案同预算内取得时才保留复杂拓扑；否则取消该层 |
| H4：研究与输出能改变下一行动，而不是只加报告内容 | 一个公开决定性问题＋一个私有核验问题；先有源研究，再让人选择下一验证及停止条件 | 公开问题有正文和覆盖终态，结果改变/明确维持一个关键判断并说明原因；私有问题不被伪造解决；行动有对象、责任、验收、期限和上限；没有新研究授权时此项仍未验证 |
| H5：用户得到的净收益足以覆盖复杂度 | 使用未看过答案的独立审阅者，或按不重叠证据簇交叉平衡比较人工与工具；计入准备、配置、纠错、复核、费用与失败处置，最后做 Windows 同路径验收 | 建议先以总人工时间下降至少30%、决定性判断质量不降为效用门，报告绝对时间、一次性基准成本和每案成本；同人顺序重读仅作观察，不归因于工具。用户10分钟内能定位关键依据与下一行动；恢复不新增 transport |

参考由实际专业人员建立，Agent 可整理，不能代签。至少需要技术/产业审阅与投资/行动负责人两种职责；可以由具备相应能力的人兼任部分职责，但参考争议必须有独立复核，不能只有模型互相同意。

专家无法形成一致参考时，应区分“允许的专业分歧”与“无来源错误”。合理分歧可定义允许答案集、缺证边界与翻转条件，不为了测得一个数字强造唯一黄金等级。若决定性分歧无法界定，先方法审议，不开始模型竞赛。

**特别限制：** 受限事实正向通过不证明技术准则 met 的正向能力。未来要自动输出 TRL5/6 支持，必须另有人工审定、配置/环境/结果完整的真实正向技术记录；没有这种材料，就不得宣称已验证该能力。

## 9. 建议的替代业务闭环

建议名称：**F1 一单元尽调优先级验证**。这是本轮候选简称，不是对仓内历史阶段或 N1 的状态替换。

### 9.1 问题与边界

以微玖现有 BP+四访谈作为完整材料池，建议焦点是“AR 单绿微显示器件进入二供验证所需的下一步事实”。先核定它确实是对应交付/验收单元；单片全彩等保留为防串单元对照，不按报告既有三/五单元数量凑清单。

用户应获得：**哪些陈述可信到什么程度，哪些反对意见成立，最该先验证哪一项，以及验证失败时为什么停止。**

此阶段不生成完整六维等级或正式 D1/D2，不声称批准投资、付款或签约。行动建议送实际负责人判断；若希望形成正式 D1，必须另行批准组织政策及完整所需分析范围，不能把本阶段手工短文伪装成产品 D1。

### 9.2 顺序

1. **先完成基准准备，不写产品代码。** 从现有索引定位材料，记录输入、时点、单元候选、来源关系与争点；取得实际审阅人和参考边界。已有高管/客户访谈用于跨来源理解，不能自动取得外发许可。
2. **先验证人能否给出可用判断。** 人工用固定材料形成短行动建议和逐主张参考，记录工时、争议与无法裁定项；没有这一结果，就不投入自动化接线。
3. **冻结开发集与留出集，再作获准的真实模型试验。** 页17已知负例只用于开发；先在完整获准材料池中测试自主定位，再做未提示答案出处的留出判断。原始模型输出、复核前后变化及人工修正分列，不以修完后的答案冒充模型原始正确率。只有选定片段获准外发时，发现能力明确未验证，不缩小分母后宣称通过H1。
4. **研究只增加一个决定性公开问题。** 离线阶段仅整理来源候选与查询计划；需要新的抓取/模型调用必须独立批准。在没有实际获取和专业消费前，研究能力继续记未验证。私有问题只形成具体 RFI，不联系任何人。
5. **只有专业判别有价值，才写最少接线。** 复用现有 Store/Journal/队列；按受测输入补用途合同、专业状态和中文记录；不先搭完整多单元/六维/报告产品。
6. **通过同一 Windows 产品路径再交付。** 目标用户从已授权附件发起、确认范围、阅读结果和精确恢复；模型试验单独跑通只算能力试验，不算宿主产品已交付。

这不是另一个无限前置文档工程：准备包只需输入清单、12项左右参考表、待审方法问题和一页实验卡；字段细化不产生新一轮架构方案。真正的下一证据是人工参考与真实判别结果，不是又一份更长的计划。

### 9.3 完成、停止与转向

| 结果 | 明确决定 |
|---|---|
| H1/H2成立，人工时间/用户理解有改善，H3对抗有增益 | 接入最小产品链，通过 H4/H5 后进入受限使用；不自动扩完整六维 |
| H1/H2成立，但 H3无增益 | 简化为单分析员模型＋人工主审，停止多角色拓扑投入 |
| 模型在一轮集中修正和一次全新留出复验后仍有关键错误，或靠全不足才安全 | 停止自动专业裁定路线；模型限于抽取、检索、对照和起草，人工负责 Finding/准则与行动 |
| 人工参考本身无法成立、没有实际专业负责人 | 停止专业自动化实现；只能交材料工作台或暂停项目，不以 Agent 自签替代 |
| 判断有用，但 Windows 接线失败 | 只修受影响宿主/合同模块；业务试验结果保留，不重写整个仓 |
| 人工直接阅读已足够高效，工具不能产生可测净收益 | 停止本轮产品化扩张；保留检索/证据管理小工具，不继续以代码增长证明价值 |
| 材料、方法或外部结果仍未知 | 如实记未完成；不把未验证解释成技术不可行、企业不值得尽调或业务 NO |

建议止损：基准准备最多2个工作日，超过后仅交精确缺项；专业试验最多一个获批窗口、一次集中修正后另获授权的留出复验，不无限换模型或换 Case。工程集成同类问题两次集中复验仍失败时停下评估模块替换。期限与次数是建议投入界限，不是当前授权。

若未来转人工主审，人工必须能提交有来源、有责任的专业意见，并使新判断形成新版本；不能仍禁止人作语义裁定，却要求人仅给机器答案盖章。应保留禁止改写原件/旧结果，调整的是谁对新结论负责，须 Owner 明确采用。

## 10. 需要 Owner 集中决定的事项

已知路径、输入历史和实现状态不再要求 Owner 重述。真正需要决定的只有：

1. **产品责任定位：** 是否采用本报告建议，近期以“人工负责、机器辅助”的验证方式推进，暂不宣称自动专业决策。推荐采用。
2. **专业负责人和行动用户：** 谁能审技术/产业证据，谁代表投资/资源配置方评价下一行动是否有用；不得默认 Owner 独自承担全部审阅。
3. **验证问题与时点：** 是否采用单绿二供验证焦点及 BP+四访谈；建议新建明确标为“历史材料复核”的评估身份，不自动继承旧截止或宣称材料反映2026年9月的经营现状，也不回改旧Case时点。实际业务资源上限由行动负责人确认。
4. **后续真实动作：** 待参考成立后，一次批准模型/研究的精确外发片段、模型、窗口、预算和可查询来源。当前旧预算/窗口不续用，N1建议的费用上限也不是本轮授权。
