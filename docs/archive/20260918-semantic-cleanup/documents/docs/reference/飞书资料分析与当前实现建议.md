## 7. 对当前N1窄业务闭环的具体影响

本次只形成设计输入，不修改阶段实现或自动升级方法。

### 7.1 应进入当前合同/验收的内容

1. **单元边界明确。**当前两准则试点可以继续，但要写清一个候选单元及未覆盖范围，不能用公司名称暗示已完成多产品全评估。
2. **复核必须检查维度语义。**保持“引用正确但解释跨越”的负例；把材料计划写成已完成测试属于阻断。
3. **统一恢复语义。**已封存结果的精确重放不再调用；修改表达不重新改变业务判断；新的事实/时点/方法才建立新评估身份。
4. **许可在角色运行前闭合。**旧失败包反复出现Evidence use license与实际输入不一致；用途模块必须连同请求、消费、runner、trace一起接通，不能停在纯函数。
5. **实际Windows入口留原错误。**测试断点恢复、阶段状态与错误一致，不隐藏成一个通用异常；不把环境问题记成企业业务NO。
6. **人工标准和实际输出分离。**同事报告/成功样本只给审阅者作参考，不能喂给被测模型后再宣称独立质量通过。

### 7.2 记录但不扩成本阶段阻断的内容

- 完整多单元、共享FRL、六维多轮对抗与跨维D1留在完整产品阶段。
- 8/28的历史暴露注册表、匿名校准活动、完整authority体系不整套搬入N1；只先继承其保护目标。
- 外部市场/专利/社区研究是完整产品需求，不因N1窄实验缺少全部研究就无限扩任务。
- 最早版本已定位；行数口径差异、尚未回传的后续source revision，不阻断当前已有依据的窄闭环。
