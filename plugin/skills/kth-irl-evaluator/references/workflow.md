# 产品工作流

## 启动

1. 从用户消息提取显式附件、行动问题及本次许可。不要递归寻找额外材料或打开旧Case。没有明确路径先向用户澄清。
2. 核对宿主实际文件读取、代码执行、独立上下文和可保存执行记录能力。能力声明不是独立性证明。
3. 按宿主合同由Agent生成内部提交JSON，调用包内工具`agent prepare --case-dir <新Case> --input <内部输入>`。保留返回的精确run_id；之后`agent status`和`agent advance`均须这个ID。
4. 读取阻断，调用`agent materials`核对全部接收输入/ZIP成员/未处理页；用`agent batches`读取所有发现批次，包括全部片段与偏移，不挑选某一页。不支持、扫描或读取失败不表示业务事实不存在。

## 集中确认

给用户展示全部材料覆盖、主体/单元候选、排除与未决原因，以及时点、有限行动和权限。用户只确认业务边界。未决单元不偷偷吸收，不凭文件标题证明事实。

范围发现任务成功封存后，用`agent propose-scope --run-id ... --task-id ...`
核验候选原文引用。Agent根据用户一次集中确认生成内部确认输入，经
`agent confirm-scope --run-id ... --input ...`冻结，随后`agent scope`可查看
原候选与修改差异。范围确认不授予证据资格或真实外发许可；离线工程中
确认贡献仍标为simulated。没有确认行动可保持null，后续不能给业务决定。

## 任务与恢复

- 使用`agent tasks`读取合法任务。任务正文、输入摘要、角色及允许材料绑定，不改写任务身份。
- 当前`begin-task`仅接受离线`simulated`。真实路径尚未授权，不能改标签绕过。
- 按合同封存返回后调用`advance`。用量不可得时保留null；失败返回不带业务结论。
- 重新进入Case先读取status，再消费封存；`outcome_unknown`禁止重发。追问使用已有事实，不默认新建Case重置预算。
- 只能操作本次获准新建Case或工作副本。`status`也会打开/迁移数据库及处理Journal，并非无写入的文件查看；保护Case先具名完整复制（含现存WAL/SHM）并核对源前后稳定与副本hash，只操作副本，不直接用本工具打开保护原件。

材料或确认范围改变需新run并注明revision父run与原因，旧确认不覆盖。研究、
专业六维、决定及报告尚待后续包接线；没有具名结果时不得自由补写评估报告。
